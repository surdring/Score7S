# 7S评分系统交互优化分析报告

> 分析日期：2026-03-27  
> 分析依据：UI截图 + 变更计划文档 + 现有代码

---

## 一、 核心结论：方案A+B可同时采用

**方案A（步进器）** 适合**微调扣分**场景，**方案B（快捷标签）** 适合**快速定位**场景，两者功能互补。

**推荐UI布局**（从上到下）：

```
┌─────────────────────────────────────────┐
│  最高分: 20分    低分阈值: 8分          │
├─────────────────────────────────────────┤
│  ┌─────┐  ┌───────────────┐  ┌─────┐   │
│  │  -  │  │      20       │  │  +  │   │  ← 步进器（方案A）
│  └─────┘  └───────────────┘  └─────┘   │
├─────────────────────────────────────────┤
│  [满分20] [18微瑕] [15较差] [10极差]    │  ← 快捷标签（方案B）
└─────────────────────────────────────────┘
```

---

## 二、 交互逻辑设计

| 操作 | 行为 |
|------|------|
| 点击 `-` | 当前分数-1，最低0，不触发键盘 |
| 点击 `+` | 当前分数+1，不超过最高分，不触发键盘 |
| 点击快捷标签 | 直接设为对应分数，不触发键盘 |
| 点击输入框 | 唤起数字键盘，可手动输入任意值 |
| 失焦/完成输入 | 自动边界校验（<0修正为0，>max修正为max） |

---

## 三、 各维度优化建议汇总

### 3.1 交互体验优化（核心：减少键盘唤起）

| 建议 | 优先级 | 实现方案 |
|------|--------|----------|
| **步进器（方案A）** | 高 | 输入框两侧添加 `-` `+` 按钮，默认分数设为满分，支持扣减式打分 |
| **快捷标签（方案B）** | 高 | 20分项提供 `[满分20]` `[18微瑕]` `[15较差]` `[10极差]` 等预设按钮 |
| **实时总分计算** | 中 | 左下角 `当前总计 X 分` 实时响应，分数变化立即跳动显示 |
| **自动滚动聚焦** | 低 | 完成一项后自动滚动到下一项（微信confirm-type="next"有限制） |

### 3.2 视觉排版优化

| 建议 | 优先级 | 实现方案 |
|------|--------|----------|
| **头部信息压缩** | 中 | 日期/部门/办公室改为一行内紧凑展示，去掉input-like样式，为评分项腾出空间 |
| **输入框视觉增强** | 中 | 分数区域加粗放大，或采用底色高亮，强化视觉焦点 |
| **进度指示器** | 中 | 顶部固定栏显示 `已评: 3 / 7项`，让用户对工作进度有预期 |

### 3.3 逻辑与功能优化

| 建议 | 优先级 | 实现方案 |
|------|--------|----------|
| **文档错误纠正** | 高 | 第70行 "20分项≤4分" 应改为 "20分项≤8分"，"10分项≤2分" 应改为 "10分项≤4分" |
| **低分强制提示** | 中 | 分数≤阈值时，备注placeholder `(选填)` 变为红色 `(必填)`，边框同步变红 |
| **实时输入拦截** | 中 | 输入超过最大值时，失焦自动修正为满分，并轻提示Toast |
