# Project Rules (AGENTS) - 职能部室（办公室）7S联查评分小程序

## 0) 绝对红线 (Absolute Directives)
所有 AI 助手在执行任务时，必须将以下原则置于最高优先级：
1. **中文沟通**：始终使用中文回复与编写文档（代码注释、英文错误码除外）。
2. **防过度设计 (KISS & YAGNI)**：
   - **严格禁止**超前实现、预测性编码、炫技式抽象。
   - **只实现当前任务明确要求的功能**。多写一行无用代码视为 Blocker。
   - 首选项目已有基础库 / 微信小程序标准 API，拒绝重复造轮子。
3. **真实集成 (No Fake Mocks)**：
   - **所有代码必须使用真实微信云开发服务进行集成和测试**。
   - **禁止使用 mock**：云函数测试中不得使用 mock 对象、mock 服务。
   - **配置缺失 => 测试失败**：缺少云开发配置必须抛出清晰错误提示。
4. **零技术债务 (Zero Tech Debt)**：
   - **零遗留项原则**：任务完成时不得存在任何 `TODO`、`待补充`、`后续优化`。
   - **审查问题闭环**：所有审查报告中的问题必须 100% 修复或证明不适用。

## 1) 编码与架构规范

### 1.1 技术栈与校验边界
- **前端 (微信小程序)**：使用 TypeScript 开发，强制类型注解（**禁止 `any`**）。
- **后端 (微信云函数)**：Node.js 环境，使用 TypeScript 编写云函数。
- **数据库**：微信云数据库（NoSQL），集合设计遵循需求文档定义。
- **存储**：微信云存储，用于存放现场照片。
- **错误处理**：云函数返回结构化错误（code, message, requestId），`message` 使用中文便于用户理解。

### 1.2 配置化开发 (强制)
- **所有配置外部化**：云开发环境 ID、数据库集合名称等通过配置文件管理。
- **部门数据配置**：当前部门数据（17个部门35个办公室）内嵌在 `miniprogram/data/departments.json`。
- **环境配置**：`project.config.json` 中配置云开发环境，`.env.example` 必须完整。

### 1.3 7S联查评分核心架构约束
- **评分项定义**：7个评分项（桌面摆放、地面、窗台、文件资料、电器设备、办公椅、整体印象），每项最高10分。
- **低分强制验证**：单项评分 ≤4分时，必须上传照片或填写备注，否则禁止提交。
- **防重复机制**：同日期同办公室已评分时，弹出二次确认提示。
- **红黑榜算法**：
  - 红榜：总分前3名
  - 黑榜：总分倒数前3名（排除满分70分、与红榜同分的记录）
- **数据完整性**：每条检查记录必须包含日期、检查员、部门、办公室、7项评分明细、总分。

## 3) 自动化验收与测试规范

### 3.1 测试要求
每个功能模块必须进行以下验证：
1. **功能验证**：在微信开发者工具中测试完整功能链路。
2. **边界验证**：测试低分验证、防重复、空数据等边界情况。
3. **云函数验证**：云函数上传后必须进行真实调用测试。

### 3.2 验证命令执行标准
- **小程序编译**：在微信开发者工具中点击"编译"验证。
- **云函数部署**：右键云函数目录选择"上传并部署：云端安装依赖"。
- **云函数本地调试**：使用微信开发者工具的云函数本地调试功能。
- **数据库验证**：通过云开发控制台查看数据是否正确写入。
- *注：若因环境缺失无法运行，必须记录原因与补测计划，不得直接标记完成。*

## 4) 微信小程序开发规范

### 4.1 页面结构规范
| 页面 | 路径 | 功能描述 |
|------|------|----------|
| 首页 | `pages/home/home` | 展示红黑榜排名，查看最新检查结果 |
| 评分页 | `pages/score/score` | 现场检查打分，支持拍照存证 |
| 分析页 | `pages/analytics/analytics` | 数据统计分析，趋势图表展示 |
| 历史页 | `pages/history/history` | 历史记录查询，支持导出Excel |
| 详情页 | `pages/inspection-detail/inspection-detail` | 单条检查记录详情展示 |
| 成功页 | `pages/score-success/score-success` | 评分提交成功后的反馈页面 |

### 4.2 云函数规范
| 云函数 | 功能描述 |
|--------|----------|
| `getLeaderboard` | 获取最新一期红黑榜排名数据 |
| `getAnalytics` | 获取统计分析数据（趋势、部门对比、问题项） |
| `exportReport` | 导出Excel/CSV报告，含完整评分表和红黑榜 |
| `clearAllData` | 清空所有数据（管理员功能） |

### 4.3 数据库集合规范
- **集合名称**：`inspections`
- **字段规范**：遵循需求文档 5.1 节定义的 TypeScript 接口
- **索引建议**：date（降序）、department、room 建立索引

### 4.4 UI/UX 规范
- **移动端优先**：采用卡片式流式布局，适配手机屏幕。
- **评分按钮**：每项使用 `[10分]` `[8分]` `[4分]` `[2分]` 四个快捷按钮。
- **红黑榜样式**：红榜前三名使用金银铜奖牌样式，黑榜使用红色警示图标。
- **表单验证**：校验失败时自动平滑滚动定位到未完成项。
