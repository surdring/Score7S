# 职能部室（办公室）7S联查评分小程序
## 项目及架构设计文档 (V1.0)

> **小程序简介**：这是一款面向企业职能部室的7S联查数字化管理工具，支持检查员通过手机现场对办公室环境进行7大项（桌面摆放、地面、窗台、文件资料、电脑设备、办公椅、整体印象）标准化评分，拍照存证，自动生成红黑榜排名及数据分析报表，实现7S检查全流程移动化、可视化、智能化。

### 1. 项目背景与目标
#### 1.1 项目背景
目前公司职能部室的7S联查采用传统纸质表格或Excel进行记录。此模式存在以下痛点：
*   **效率低下：** 现场记录后需回办公室二次录入电脑，人工统计总分、排名耗时费力。
*   **缺乏直观证据：** 纸质打分难以关联现场实况，扣分项容易引起部门间争议（“扯皮”）。
*   **数据滞后：** 领导无法实时掌握检查结果，历史数据难以沉淀和多维分析。

#### 1.2 项目目标
开发一款基于微信生态的内部办公小程序，实现7S联查的**全面数字化**：
1.  **移动化打分：** 检查人员持手机即可完成现场打分。
2.  **存证可视化：** 评分与现场照片/文字备注强绑定，做到“有图有真相”。
3.  **统计自动化：** 提交后系统秒级自动计算总分，并生成“最优前3名”与“最差前3名”排行榜。

### 2. 核心功能需求说明 (PRD)

系统主要面向三类用户角色：**检查员**（负责打分上传）、**管理员/领导**（查看全局数据与红黑榜）、**各部门负责人**（查看本部门成绩及问题照片）。

#### 2.1 现场检查打分模块 (检查员端)
*   **检查目标选择：**
    *   默认当前日期（格式：YYYY-MM-DD）。
    *   级联选择器：选择部门（17个部门） -> 选择具体办公室（共35个办公室）。
    *   自动定位当天第一个未评分的办公室，提高效率。
*   **标准化评分表单：**
    *   7个评分项：桌面摆放、地面、窗台、文件资料、**电器设备**、办公椅、整体印象。
    *   **评分分值体系（100分制）：** 总分上限为 100 分；其中 `地面/桌面摆放/电器设备` 单项满分 20 分，其余 4 项单项满分 10 分。
    *   **快捷单选评分：** 摒弃手动输入数字，每项下方提供 4 个快捷分值按钮，点击高亮即选中。
        *   满分 20 分的项目：`[20分]` `[16分]` `[12分]` `[8分]`
        *   满分 10 分的项目：`[10分]` `[8分]` `[6分]` `[4分]`
    *   **评分标准提示：** 每个评分项下方显示具体评分标准（如"满分：整洁有序；80%：轻微杂乱..."）。
*   **📸 拍照存证与备注（核心要求）：**
    *   每个评分项下方设置 `[拍照/相册上传]` 按钮（最多支持传3张/项）及文本输入框。
    *   **业务逻辑校验：** 单项评分 ≤4分时，**强制要求**必须上传照片或填写备注说明原因，否则无法提交。
*   **智能防重复机制：**
    *   同一日期、同一办公室已评分时，系统会弹出二次确认提示，避免重复提交。
    *   记录当天已评分办公室列表，自动切换到同部门下一个未评分办公室。
*   **智能汇总与提交：**
    *   系统实时累加7项分数，底部悬浮显示"当前总计：XX 分"。
    *   表单校验失败时自动平滑滚动定位到未完成评分项，便于快速补全。
    *   提交后展示"提交成功"页面，支持查看详情、返回首页、继续打分。

#### 2.2 数据排行与大屏展示模块 (领导/全员查看端)
*   **🏆 自动红黑榜（核心要求）：**
    *   每次全厂联查结束后，系统自动基于总分进行降序排列。
    *   **红榜（Best 3）：** 展示排名前3的办公室名称、总分。
    *   **黑榜（Worst 3）：** 展示排名倒数前3的办公室名称、总分。
    *   *同分处理逻辑：若存在同分，则并列显示或按提交时间先后排序。*
*   **数据分析（Analytics）：**
    *   新增独立“数据分析”页面，并集成到底部导航栏。
    *   **整体趋势（折线图）：** 展示随时间推移的全公司各部门平均分变化趋势。
    *   **各部门平均分对比（柱状图）：** 按部门聚合平均分并排序，便于横向对比。
    *   **扣分重灾区（雷达图）：** 按7个检查大项聚合平均得分，识别薄弱项以开展专项整改。
*   **问题曝光台：**
    *   点击黑榜部门，可直接展开查看其被扣分项目的**现场照片**和备注，直观暴露问题。
*   **联查简报分享：**
    *   支持将当期红黑榜一键生成为精美长图，方便转发至公司微信群通报。

#### 2.3 历史记录与管理模块
*   **历史明细查询：** 可按"日期"或"部门名称/检查员姓名/备注内容"检索过往的所有打分表单和照片记录。
    *   **增强搜索：** 搜索框支持同时匹配部门名称、检查员姓名、日期（如输入 `03-25`）、评分项或备注内容，并实时过滤列表。
    *   **日期筛选：** 支持按具体日期筛选，默认显示最新日期。
*   **导出功能（历史页面右上角）：**
    *   支持导出 **Excel (xlsx)** 格式，含完整样式和红黑榜两个工作表。
    *   导出数据遵循当前筛选条件（日期、关键词）。
    *   **Excel结构：**
        *   Sheet 1：`7S评分表` - 完整评分记录，含部门、办公室、7项评分明细、总分
        *   Sheet 2：`红黑榜排名` - 当日红榜（Top 3）和黑榜（Bottom 3）
    *   无记录时导出按钮置灰禁用，避免导出空文件。

### 4. 技术架构设计方案

为追求高开发效率、低运维成本及与微信群的无缝对接，强烈推荐采用 **微信小程序原生开发 + 微信云开发 (Tencent CloudBase) Serverless 架构**。

#### 4.1 系统架构图概览
```text
[用户层]    微信小程序前端 (检查员打分 / 领导看报表 / 部门看通报)
   ↓↑
[逻辑层]    微信云函数 (Node.js) -> 处理算分逻辑、红黑榜排序算法、权限校验
   ↓↑
[数据层]    微信云数据库 (NoSQL) -> 存储部门列表、打分明细记录
[文件层]    微信云存储 (Cloud Storage) -> 存放所有现场拍摄的照片 (CDN加速)
```

#### 4.2 为什么选择“微信云开发”？
1.  **免服务器运维：** 无需额外购买阿里云/腾讯云服务器，无需配置域名备案.
2.  **原生鉴权：** 天然支持微信一键登录获取用户身份，安全性高.
3.  **快速读写照片：** 拍照上传直接存入云存储，并返回fileID存入数据库，开发极其简单.

#### 5.2 红黑榜排序算法

```javascript
// getLeaderboard 云函数核心逻辑

// 1. 获取最新检查日期
const latestDateRes = await db.collection('inspections')
  .orderBy('date', 'desc')
  .limit(1)
  .get();

// 2. 获取该日期所有记录，按部门+办公室分组取最高分
const groupedMap = new Map();
records.forEach(record => {
  const key = `${record.department}-${record.room}`;
  if (!groupedMap.has(key) || groupedMap.get(key).totalScore < record.totalScore) {
    groupedMap.set(key, record);
  }
});

// 3. 排序分组后的记录
const groupedRecords = Array.from(groupedMap.values());
groupedRecords.sort((a, b) => b.totalScore - a.totalScore);

// 4. 红榜：前3名
const redList = groupedRecords.slice(0, 3);
const redMinScore = redList.length > 0 ? redList[redList.length - 1].totalScore : 0;

// 5. 黑榜：从倒数取，排除满分100分、与红榜同分的记录，最多3个
const blackList = [];
for (let i = groupedRecords.length - 1; i >= 0; i--) {
  const record = groupedRecords[i];
  if (record.totalScore === 100) continue;          // 排除满分
  if (record.totalScore === redMinScore && redList.length >= 3) continue; // 排除与红榜同分
  if (redList.some(r => r._id === record._id)) continue; // 排除已在红榜中
  
  blackList.push(record);
  if (blackList.length >= 3) break;
}

// 6. 黑榜按分数从低到高排序
blackList.sort((a, b) => a.totalScore - b.totalScore);
```
